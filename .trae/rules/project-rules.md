# 项目规则（TRAE Project Rules）

本文件与根目录 `AGENTS.md` 的核心规则一致，供 TRAE 项目规则持久化使用。

## 1. 操作范围

- 仅在本项目（知识网站目录）内进行写入操作，不触碰其他任何目录。

## 2. 对原有项目始终只读

- 对原有两个项目（注册监理工程师知识库、OpenMAIC）始终只读：
  - 不修改、不删除、不移动、不重命名、不覆盖其任何文件；
  - 不改其 Git 状态、配置或依赖；
  - 不自动整理或批量迁移；
  - 不整体复制其文件夹。

## 3. 素材复制与追溯

- 仅复制经核对选中的单个文件，保留原文件。
- 在《素材来源清单》（位于 `项目管理/`）记录原始路径、版本、复制日期、目标位置。
- 所有文件来源必须可追溯；未取得公开发布授权的资料不得公开。

## 4. 文件与目录管理

- 技术文件名可用英文；用户管理文件及说明用简体中文。
- 每个主要目录有明确用途；生成文件有唯一正式存放位置；临时文件与正式成果分开。

## 5. 公开内容与发布规则

- 禁止把原始教材 PDF、未授权资料、内部工作文件放进公开目录（`docs/`）。
- 2026-10-26 用户明确授权：整理后的第一至第三章网页正文及必要配图可进入公开仓库并通过 GitHub Pages 发布；后续章节按同一流程逐章发布。
- 发布流程：完成一章 → AI 核对 → `npm run build` 与 `npm run check` 通过 → 提交推送 → 线上验证；正常发布不再逐次等待人工验收。
- AI 核对不等于人工验收，三类状态分别在 `项目管理/验收记录.md` 记录。
- 原始 PDF、`待审核素材/`、`项目管理/` 与 `.trae/specs/` 不进入公开仓库；公开正文 frontmatter 不保留内部管理字段。
- 发布检查不设豁免项；不重写 Git 历史、不强制推送。

## 6. 交付质量

- 不用重复的报告或测试文档代替实际网站成品。
- 每次任务只围绕当前目标做必要修改。

## 7. 可维护性

- 项目完成后必须能用中文说明如何使用和维护。
