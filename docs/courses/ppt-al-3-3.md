## 两份文件：一份管全局，一份管专项

<p class="dk-lead">监理规划是项目监理机构全面开展监理工作的<strong>指导性文件</strong>，监理实施细则是针对专项的<strong>操作性文件</strong>。</p>

- **监理规划**：由总监理工程师组织编制，覆盖质量、造价、进度和安全生产管理，解决「这个项目怎么监理」。
- **监理实施细则**：在规划基础上编制，针对专业性较强、危险性较大的分部分项工程或某一专项目标，解决「这道工序怎么盯」。
- **两个时点**：规划在第一次工地会议前报建设单位；细则在相应分部分项工程开始前编制完成。
- **一条关系**：先有规划、经建设单位确认，才有编制细则的依据。

<template #notes>

这一节内容不多，但考的都是细节：谁编制、谁审核、什么时候报、谁批准。先把「指导性」和「操作性」这组定位立住，后面的编制人、编制依据、报审程序都能顺着推：管全局的层级高、报得早；管专项的层级低、编得晚。

</template>

## 监理规划的十项内容

<span class="dk-tag">工程概况</span><span class="dk-tag">监理工作范围和依据</span><span class="dk-tag">监理工作目标和内容</span><span class="dk-tag">项目监理机构和人员进退场计划</span><span class="dk-tag">监理工作程序、方法和措施</span><span class="dk-tag">监理工作制度</span><span class="dk-tag">监理设施与设备</span><span class="dk-tag">监理工作重点和难点</span><span class="dk-tag">监理工作进度计划</span><span class="dk-tag">监理工作风险管理</span>

<Reveal label="十项内容怎么分组记？">

- **先交代对象**：工程概况、监理工作范围和依据、监理工作目标和内容。
- **再交代怎么干**：项目监理机构和人员进退场计划、监理工作程序方法和措施、监理工作制度、监理设施与设备。
- **最后交代难点与安排**：监理工作重点和难点、监理工作进度计划、监理工作风险管理。

</Reveal>

<template #notes>

十项按「对象—方法—难点安排」三组记，比逐条背省力。注意「监理工作制度」是规划的内容，不是监理大纲的内容，这两份文件经常被放在一道题里混淆。还有「监理设施与设备」容易被漏，它管的是监理自己用的办公、检测、通信条件。

</template>

</Slide>

## 编制要求：四条标准

<Steps title="监理规划编制的四项要求" :steps="[
  { t: '基本框架力求统一', d: '同一监理单位内部的规划框架保持一致，便于审核、比较和交底' },
  { t: '内容深度具有针对性和可操作性', d: '针对本工程的特点写，措施要能落地，不抄范本、不写空话' },
  { t: '表达形式科学规范', d: '图表、流程、岗位职责表达清楚，术语和表式符合规范' },
  { t: '具有动态调整机制', d: '设计、施工组织设计、工期和质量要求发生重大变化时能及时修改' }
]" />

> 四条要求对应四个常见毛病：框架五花八门、内容照抄范本、表达含糊、编完就锁进柜子。

<template #notes>

四条要求可以反过来当检查表用：框架统一不统一、内容有没有针对性、表达规不规范、有没有动态调整。第四条的动态调整机制要和后面的「调整后按原报审程序重新审批」连起来看，不是改了就算。

</template>

</Slide>

## 报审：一条链走完才能实施

<Steps title="监理规划的编制与报审流程" :steps="[
  { t: '总监组织编制', d: '签订监理合同及收到工程设计文件后，由总监理工程师组织专业监理工程师编制' },
  { t: '单位内部审核', d: '工程监理单位技术管理部门是内部审核单位，由技术负责人审核签字' },
  { t: '总监签字盖章', d: '总监理工程师签字并加盖执业印章' },
  { t: '单位审批盖章', d: '经工程监理单位技术负责人审批、加盖单位公章' },
  { t: '第一次工地会议前报送', d: '在第一次工地会议前报送建设单位' },
  { t: '建设单位确认后实施', d: '监理规划须经建设单位确认后方可实施；发生重大变化调整的，按原报审程序审核批准、确认后实施' }
]" />

<template #notes>

这条链的顺序不能乱：先内部审核，再总监签章，再单位盖章，最后报建设单位。两个章要分清：总监盖的是执业印章，单位盖的是公章。还有一个常考点：规划不是报了就生效，必须经建设单位确认后才能实施。

</template>

</Slide>

## 监理实施细则：四块内容

<Steps title="监理实施细则应包含的四项内容" :steps="[
  { t: '分部分项工程特点', d: '说清这道分项或分部工程的技术特点、难点和风险点，这是针对性的来源' },
  { t: '质量控制与安全生产管理要点', d: '列出需要控制的关键部位、关键工序和质量安全指标' },
  { t: '监理工作内容及流程', d: '把审查、巡视、旁站、验收等动作按顺序串成流程' },
  { t: '监理工作方法及措施', d: '明确用什么手段、发现问题怎么处置、谁签字谁负责' }
]" />

> 细则不是规划的缩写版：规划说「要控制什么」，细则说「这道工序具体怎么控、控到什么程度」。

<template #notes>

四项内容里第一项最容易被写空，但恰恰是「针对性」的来源。可以让学生想一个具体例子：深基坑支护的细则，特点要写地质条件、周边建筑、降水要求，控制要点要写变形监测、支护验收，流程要写旁站和验收节点。这样四项就不是四个标题了。

</template>

</Slide>

## 细则的编制依据与要求

<Steps title="监理实施细则的三项编制依据" :steps="[
  { t: '建设单位已确认的监理规划', d: '规划是细则的上位文件，未经确认的规划不能作为依据' },
  { t: '工程建设标准、工程设计文件', d: '验收规范、强制性条文和施工图是判断合格与否的尺子' },
  { t: '施工组织设计、施工方案或专项施工方案', d: '细则要盯的工序和工艺，就写在施工方的方案里' }
]" />

**三条编制要求**：内容要全面、针对性要强、具有可操作性。

> 编制时点：可随工程进展编制，但必须在**相应分部分项工程开始前**由**专业监理工程师**编制完成——不能等干完了再补。

<template #notes>

三项依据有先后：先有经确认的规划，再有标准和图纸，最后对照施工方的方案。编制时点是本节最爱考的地方，注意两个限定：一是「相应分部分项工程开始前」，不是开工前统一编完；二是编制人是专业监理工程师，不是总监。另外可以补充：编制时还可融入单位已建立的质量管理体系和职业健康安全管理体系内容。

</template>

</Slide>

## 小结：先规划、后细则，编制与审批各归其位

<p class="dk-lead">规划管全面、要报建设单位确认；细则管专项、总监批准即可用。</p>

- **定位**：规划是指导性文件，细则是操作性文件；细则以经确认的规划为依据。
- **内容**：规划十项，按对象、方法、难点安排三组记；细则四项，特点是前提、要点是核心、流程和方法是抓手。
- **程序**：规划由总监组织编制，技术负责人审核签字，总监盖执业印章、单位盖公章，第一次工地会议前报送，建设单位确认后实施。
- **时点**：细则在相应分部分项工程开始前由专业监理工程师编制完成，报总监审查批准；修改后经总监批准即可实施。
