## 五大比较方法全景：各自看什么？

<p class="dk-lead">实际进度与计划进度的比较是工程进度监测的主要环节。常用方法有<strong>横道图、S 曲线、香蕉曲线、前锋线和列表比较法</strong>。</p>

## 匀速进展横道图：四步画法与位置判定

<CompareCard title="例题读图：右端位置就是判据" :cols="['进度判定', '时间偏差']" :rows="[

  { k: '与检查日期重合', v: ['实际进度与计划进度一致', '累计完成任务量与时间成线性关系'] },

> **适用边界**：工作从开始到结束的整个过程中，进展速度固定不变；进展速度变化时不能套用这种方法。

<template #notes>

匀速进展的意思是单位时间完成的任务量相等，所以任务量和时间是线性关系。画图时按计划、检查日期、实际粗线、对比分析这四步来，不要漏掉检查日期。判断时只看涂黑粗线右端，左拖后、右超前、重合一。这个方法有明确边界，一旦工作进展速度发生变化，就不能只靠粗线位置下结论。

## 非匀速进展横道图：线上计划%，线下实际%

<p class="dk-lead">横道线上方标<strong>计划累计完成百分比</strong>，下方标<strong>实际累计完成百分比</strong>；涂黑粗线另外表示实际开始、完成、持续时间及连续或间断情况。</p>

<div style="overflow-x: auto">
<table>
<caption style="text-align: left">例 4-1：基槽开挖第 4 周末检查</caption>
<thead><tr><th>时间</th><th>第 1 周</th><th>第 2 周</th><th>第 3 周</th><th>第 4 周</th></tr></thead>
<tbody>
<tr><th>线上：计划累计</th><td>10%</td><td>25%</td><td>45%</td><td>65%</td></tr>
<tr><th>线下：实际累计</th><td>8%</td><td>22%</td><td>42%</td><td>60%</td></tr>
<tr><th>实际 − 计划</th><td>−2%</td><td>−3%</td><td>−3%</td><td><strong>−5%</strong></td></tr>
</tbody>
</table>
</div>

- **线上 > 线下**：实际拖后，拖欠任务量为二者之差。
- **线上 < 线下**：实际超前，超前任务量为二者之差。
- **线上 = 线下**：实际与计划一致；本例第 4 周末实际拖后 **5%**。

<template #notes>

非匀速工作不能只看横道线长短，要把同一时刻的两个累计百分比放在一起比。口诀是线上计划、线下实际，用实际减计划，负数就是拖后。基槽开挖到第四周末，计划完成百分之六十五，实际完成百分之六十，所以拖欠百分之五。涂黑粗线仍然有用，但它表达的是实际作业时间和是否中断，不代表任务量百分比。

</template>

</Slide>

## 香蕉曲线：ES 与 LS 怎样形成包络？

<p class="dk-lead">对同一网络计划，全部工作分别按<strong>最早开始时间 ES</strong>和<strong>最迟开始时间 LS</strong>安排，各绘一条累计任务量 S 曲线。</p>

<Steps title="香蕉曲线的形成原理" :steps="[

  { t: '分别累加任务量', d: '按两种安排分别确定单位时间任务量，再累加得到项目累计任务量或百分比' },
  { t: '绘制两条 S 曲线', d: 'ES 曲线与 LS 曲线起点、终点相同，一般 ES 曲线在 LS 曲线左侧，组成闭合包络' }
]" />

<CompareCard title="实际进展点落在哪里？" :cols="['进度判断', '管理含义']" :rows="[
  { k: '香蕉形区域之内', v: ['实际进度处于正常范围', '科学合理的优化进度曲线也应位于包络区域内'] },
  { k: 'ES 曲线左侧', v: ['比全部工作按最早开始时间安排还要超前', '可结合实际曲线预测后期进展'] },
  { k: 'LS 曲线右侧', v: ['比全部工作按最迟开始时间安排还要拖后', '应及时分析并采取措施'] }
]" />

<template #notes>

香蕉曲线不是另外找一条曲线，而是把 ES 和 LS 两种安排下的 S 曲线画在一起。两条曲线的总任务量相同，所以起点和终点相同，中间形成包络区域。实际点落在区域内说明进展处于正常范围，落在 ES 左侧表示超前，落在 LS 右侧表示拖后。绘制时最要紧的是分别按两种时间安排计算每期任务量，再逐期累加。

</template>

## 前锋线比较法：时标网络三步判定

<Steps title="从标点到影响分析" :steps="[

  { t: '第二步：看左右与水平距离', d: '前锋点在检查日期左侧=拖后，右侧=超前，重合=一致；水平距离就是拖后或超前时间' },
  { t: '第三步：结合 FF 与 TF', d: '与自由时差比较判断是否影响紧后工作最早开始，与总时差比较判断是否影响总工期' }
]" />

<CompareCard title="两个时差不要混用" :cols="['自由时差 FF', '总时差 TF']" :rows="[
  { k: '主要判断对象', v: ['对紧后工作最早开始时间的影响', '对项目总工期的影响'] },
  { k: '拖后时间超过该时差', v: ['紧后工作最早开始时间将受影响', '总工期将受影响'] },

<template #notes>

前锋线先从检查日期出发，把各项工作实际进展位置依次连成点划线。标前锋点有两种办法，能算任务量时按比例标，只能估算剩余工作时按尚需作业时间逆向标。判偏差就看左右，左侧拖后、右侧超前，水平距离就是偏差时间。最后要分别和自由时差、总时差比较，一个看紧后工作，一个看总工期，不能只凭拖后几周就直接宣布工期延误几周。

</template>

## 列表比较法：非时标网络尚需作业时间计算

<p class="dk-lead"><strong>尚有总时差 = 检查日期到原计划最迟完成时间的剩余时间 − 尚需作业时间</strong>。将尚有总时差与原有总时差比较，而不是只看尚需作业时间。</p>

<div style="overflow-x: auto">
<table>
<caption style="text-align: left">例 4-5：第 10 周末工程进度检查比较</caption>
<thead><tr><th>工作</th><th>尚需作业</th><th>至最迟完成尚余</th><th>原有 TF</th><th>尚有 TF</th><th>判断</th></tr></thead>
<tbody>
<tr><th>F</th><td>4 周</td><td>4 周</td><td>1 周</td><td>0 周</td><td>拖后 1 周，不影响总工期</td></tr>
<tr><th>G</th><td>1 周</td><td>0 周</td><td>0 周</td><td>−1 周</td><td>拖后 1 周，影响总工期 1 周</td></tr>
<tr><th>H</th><td>3 周</td><td>4 周</td><td>2 周</td><td>1 周</td><td>拖后 1 周，不影响总工期</td></tr>
</tbody>
</table>
</div>

- 尚有 TF = 原有 TF：进度一致；尚有 TF > 原有 TF：进度超前。
- 尚有 TF < 原有 TF 且仍为非负值：拖后，但不影响总工期。
- 尚有 TF < 原有 TF 且为负值：拖后并影响总工期，影响程度取尚有 TF 的绝对值。

<template #notes>

列表比较法用于非时标网络，核心是把检查日以后的剩余时间和尚需作业时间算清楚。先用剩余时间减去尚需作业时间，得到尚有总时差，再拿它和原有总时差比较。比如工作 F 尚有总时差为零，比原有一周少一周，所以拖后一周但还不影响总工期。工作 G 的尚有总时差变成负一周，就说明不仅拖后一周，还会使总工期延长一周。

</template>

</Slide>
