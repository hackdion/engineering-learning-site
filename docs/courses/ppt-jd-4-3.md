## 第一步：是否在关键线路上

<p class="dk-lead">进度偏差的大小及其所处位置不同，对后续工作和总工期的影响程度也不同。</p>

<CompareCard title="关键工作与非关键工作的不同判据" :cols="['判断']" :rows="[
  { k: '关键线路上的关键工作', v: ['无论偏差有多大，都将对后续工作和总工期产生影响，必须采取调整措施'] },
  { k: '非关键工作', v: ['需要根据偏差值与总时差、自由时差的关系作进一步分析'] }
]" />

<Reveal label="为什么关键工作“零容忍”？">

关键工作的总时差为零（或最小），没有任何缓冲时间，因此哪怕很小的偏差也会直接传导到总工期，必须立即采取措施。

</Reveal>

<template #notes>

第一步先分清是不是关键工作。关键工作因为总时差为零或最小，没有缓冲，所以任何偏差都要调整。非关键工作有一定缓冲，才需要进入第二步、第三步，用总时差和自由时差去量化影响。这一步是最先要做的判断，也是后面两步的前提。

</template>

</Slide>

## 第二、三步：两个时差的分工

<CompareCard title="总时差与自由时差，一个看工期，一个看后续" :cols="['总时差 TF', '自由时差 FF']" :rows="[
  { k: '判断对象', v: ['偏差是否影响总工期', '偏差是否影响后续工作'] },
  { k: '偏差超过该时差', v: ['影响后续工作和总工期，必须调整', '影响后续工作，按限制条件确定调整方法'] },
  { k: '偏差未超过该时差', v: ['不影响总工期，还需进一步看自由时差', '不影响后续工作，原计划可不作调整'] }
]" />

<Reveal label="判断顺序为什么不能颠倒？">

必须先和总时差比（定是否影响总工期），再和自由时差比（定是否影响后续工作）。因为自由时差一般不大于总时差，先看大的总时差能更快缩小范围。

</Reveal>

<template #notes>

这两个时差是本节最关键的一组概念。总时差管总工期，自由时差管紧后工作。偏差超过总时差，一定影响总工期；超过自由时差，影响后续工作但不一定影响总工期。判断时先看总时差，再决定要不要看自由时差。做题时把这两条线分清楚，就不会把影响范围判断错。

</template>

</Slide>

## 排一排：偏差分析的过程顺序

<SortSteps id="ppt-jd-4-3-flow" prompt="按偏差分析判断过程，把下面四步排好" :items="[

<Reveal label="每一步“否”之后分别落到哪里？">

不在关键线路（否）→ 继续判断是否大于总时差；不大于总时差（否）→ 继续判断是否大于自由时差；不大于自由时差（否）→ 不影响后续工作，返回进度监测系统。任一步“是”→ 采取进度计划调整措施，实施新的进度计划。

</Reveal>

## 改逻辑关系：顺序改流水的实例

<p class="dk-lead">例 4-6：某基础工程含挖基槽、做垫层、砌基础、回填土 4 个施工过程，持续时间分别为 <strong>21、15、18、9 天</strong>。</p>

- **顺序作业**：总工期 = 21 + 15 + 18 + 9 = **63 天**。
- **流水作业**：在满足工作面及资源供应条件下，把基础工程划分为工程量大致相等的 **3 个施工段**组织流水作业。

<Reveal label="组织流水后的计算工期是多少？">

通过组织流水作业，基础工程的计算工期由 63 天缩短为 **35 天**。

</Reveal>

<template #notes>

这道例题很直观地说明改变逻辑关系能抢多少工期。四个施工过程如果顺序干，就是四个持续时间相加，63 天。把它们分成三段组织流水，让前后工序搭接起来，工期一下缩到 35 天。核心思想就是平行和搭接，用空间换时间。考试可能直接让判断工期数字或流水段数。

</template>

</Slide>

## 缩短持续时间：三种情况全景

  { k: '超过自由时差、未超过总时差', v: ['不影响总工期，只影响后续工作；按后续工作允许拖延的时间限制（无限制/有限制）调整'] },
  { k: '超过总时差', v: ['影响后续工作和总工期；总工期不允许拖延则压缩关键线路后续工作，允许拖延则重新绘制，允许拖延但有限则工期优化'] },
  { k: '进度超前', v: ['也要综合分析对后续工作的影响，与承包单位协商，提出合理的进度调整方案'] }

<Reveal label="为什么进度超前也要调整？">

工期目标往往是综合考虑各因素后的合理工期，超前会使资源需求变化，打乱人、材、物和资金的合理安排，多个平行承包单位施工时还会带来协调麻烦。

</Reveal>

<template #notes>

压缩持续时间时，要根据拖延的严重程度分成三种情况处理。最轻的，只超过自由时差没过总时差，只影响后续，不影响总工期；最重的，超过总时差，影响后续和总工期，这时还要看总工期允不允许拖延，允许多久，再分别用工期优化的办法处理。另外特别注意，进度超前也不是好事，同样要分析和协调。

</template>

</Slide>

## 超过总时差：总工期不允许拖延

<Steps title="例 4-8：工期不拖延时的调整思路" :steps="[

  { t: '判断限制条件', d: '项目总工期不允许拖延，必须按原计划工期 130 天完成。' },
  { t: '选定压缩对象', d: 'C 的后续工作 F、H、J 均可压缩 10 天，经比较压缩 H 代价最小。' },
  { t: '压缩并重排', d: '将工作 H 的持续时间由 30 天缩短为 20 天，调整后的计划仍按 130 天完成。' }

<template #notes>

这个例子讲的是超过总时差、且工期不允许拖延的情形。关键工作 C 拖了 10 天，直接顶到总工期。既然不允许拖延，就只能用工期优化的方法，在关键线路的后续工作里挑代价最小的压缩。这里选了 H，从 30 天压到 20 天，把工期又拉回 130 天。核心是“关键线路 + 代价最小”两个词。

</template>

</Slide>

## 超过总时差：工期允许拖延（有限）

<p class="dk-lead">例 4-10：总工期允许拖延，但只允许拖到 <strong>135 天</strong>（原计划 130 天）。</p>

<Steps title="工期拖延有限时的三步调整" :steps="[
  { t: '绘制化简的网络计划', d: '以检查日期为起点，用尚需作业时间取代原计划数据。' },
  { t: '确定需压缩的时间', d: '检查发现总工期将延长至 140 天，允许 135 天，故需压缩 5 天。' },
  { t: '进行工期优化', d: '关键线路为 C、F、H、J，压缩代价最小的 H 由 30 天缩为 25 天，满足 135 天要求。' }
]" />

<Reveal label="与“允许拖延”的情况有何不同？">

总工期允许拖延时，只需以实际数据取代原计划重新绘制即可；而允许拖延但有限制时，还要把拖延时间当作超出部分，用工期优化把超出的时间压回去。

</Reveal>

<template #notes>

这一页是“允许拖延但有限”的情况，比完全允许拖延多了一步工期优化。先化简重画，再算需要压几天（140 减 135，压 5 天），最后在关键线路上选代价最小的工作压。把 H 从 30 天压到 25 天。三种情形的区别要分清楚：不允许拖就压、允许拖就重画、允许但有限就边重画边压。

</template>

</Slide>

## 进度超前：为什么也要管？

<p class="dk-lead">监理工程师控制进度的任务不仅是防拖延，<strong>进度超前同样要处理</strong>。</p>

- 工期目标往往是综合各方面因素确定的**合理工期**，时间上任何变化都可能造成其他目标失控。
- 某项工作超前会**使资源需求发生变化**，打乱人、材、物等资源的合理安排，影响资金计划的使用。
- 多个平行承包单位施工时，还会引起后续工作时间安排的变化，给协调工作带来麻烦。

<Reveal label="监理工程师应怎么做？">

必须综合分析进度超前对后续工作的影响，并同承包单位协商，提出合理的进度调整方案，确保工期总目标顺利实现。

</Reveal>

<template #notes>

很多人以为只有拖后才是问题，其实超前也要管。原因是工期目标是权衡过的合理值，超前会打乱资源安排和资金计划，多单位并行时还带来协调麻烦。所以监理要综合分析影响，和承包单位协商调整方案。这句话在案例分析里常作为得分点，别漏了。

</template>

</Slide>

## 小结：偏差分析一张表

- **三步判断**：是否关键工作 → 偏差是否大于总时差 → 偏差是否大于自由时差，任一步“是”即需调整。
- **两种方法**：改变逻辑关系（平行、搭接、流水）或缩短关键线路、超工期非关键线路上工作的持续时间。
- **三种情形**：超过 FF 未超 TF 只影响后续；超过 TF 影响后续与总工期（按工期不允许/允许/允许有限分别处理）；进度超前也要协调调整。
