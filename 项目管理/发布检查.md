## 2026-10-22 V0.2 审计：豁免制度废除与 Git 历史清理评估

### 豁免合理性结论（对应此前"已知豁免"）

**不合理，已废除。** 此前对 `course.json` 的豁免理由是"内部追溯元数据，不影响公开性"，但该文件实际含 **240 处 `/Users/hackdion/...` 本机绝对路径**，已随公开仓库发布到互联网。暴露内容包括：macOS 用户名、本机目录结构、内部项目名与产线目录命名。虽无凭据泄露，但属于内部信息外泄，且豁免机制使检查失去了对这类问题的拦截能力。整改：

1. 第3课课件与知识文章正文移回 `待审核素材/`（公开发布授权未确认是根本原因）。
2. 脚本废除全部豁免，`/Users/` 加入特征串，命中即 FAIL。
3. `.trae/specs/`（含本机路径）与 `项目管理/` 移出公开仓库并加入 `.gitignore`。

### Git 历史清理评估

已公开的敏感内容在历史提交中仍可查看（`course.json` 的 240 处本机路径、文章与课件全文）。评估如下：

- **风险等级：低**。仓库公开仅 1 天，无凭据/密钥泄露，暴露的是用户名与目录结构；仓库无协作者。
- **可选方案 A（推荐，暂不执行）**：接受现状，待用户确认公开发布授权范围后一并处理；若用户名与目录结构介意，可随时执行方案 B。
- **可选方案 B（彻底清除）**：`git filter-repo` 或 BFG 重写历史 + force push。影响：仓库 1 天内无协作者，风险可控；但 force push 属破坏性操作，需用户明确授权后执行；GitHub Pages 历史部署不受影响，缓存可能残留至 GitHub 侧刷新。
- **决定**：本轮不执行历史重写（未经用户授权不做 force push），仅完成当前版本整改并在此登记。
